# GestureX — Smart Assistive Communication & Home Automation Glove

GestureX is an ESP32-based wearable prototype that reads finger-flex and motion sensors, sends gesture data over Bluetooth Classic, and maps selected finger patterns to home-automation relay actions. The firmware also includes emergency/help gesture messages and a basic accelerometer-threshold fall event.

## Project at a Glance

- **Controller:** ESP32
- **Firmware:** Arduino C++
- **Sensors used in the current firmware:** Four flex sensors and an MPU6050 accelerometer/gyroscope
- **Connectivity:** Bluetooth Classic using `BluetoothSerial`
- **Outputs:** Relay control for a light and a motor
- **Development environment:** Arduino IDE

## Features in the Current Firmware

- Reads four flex-sensor analog inputs and converts them to binary states using a threshold.
- Reads MPU6050 acceleration and applies a dead zone to the X and Y axes.
- Streams six state values over Bluetooth as a pipe-delimited line.
- Recognizes configured finger patterns for light and motor relay control.
- Sends `EMERGENCY` and `HELP` event strings for configured patterns.
- Sends `FALL_DETECTED` when the acceleration magnitude exceeds the configured threshold.

**Important:** These are firmware behaviors, not a claim of medically validated fall detection or a certified assistive device. The current fall event uses a simple threshold and needs real-world validation before practical safety use.

| Signal | ESP32 GPIO |

| Flex sensor 1 | 33 |
| Flex sensor 2 | 32 |

**Check your exact ESP32 board and wiring before powering the circuit.** Flex sensors need appropriate voltage-divider circuits; do not connect a bare resistive flex sensor directly as though it were a digital input.

## Gesture Logic

The firmware currently uses these four-flex-state patterns:

| Pattern (m1 m2 m3 m4) | Action |
|---|---|
| `0 0 1 1` | Motor relay ON |
| `1 1 0 0` | Motor relay OFF |
| `0 1 1 1` | Light relay ON |
| `1 0 1 1` | Light relay OFF |
| `0 0 0 0` | Send `EMERGENCY` |
| `1 1 1 1` | Send `HELP` |

The `0`/ `1` values are generated by comparing each analog reading with `FLEX_THRESHOLD` (currently 2000). Calibrate this threshold for your sensor, resistor network, board, and wearing position. The relay logic assumes an active-low relay input in the current code; verify your module's behavior before connecting a load.

## Bluetooth Data Format

The firmware advertises the Bluetooth serial device as **`SenseSpeak`**. It streams six values separated by pipe characters, for example:

```text
0|1|1|0|1|0
```

The first four values are flex states; the last two represent the thresholded X- and Y-axis acceleration states. Event messages such as `LIGHT_ON`, `MOTOR_OFF`, `HELP`, and `FALL_DETECTED` are sent separately.

## Getting Started

1. Clone or download this repository.
2. Open `Arduino_Code/GestureX_Smart_Glove.ino` in Arduino IDE.
3. Install the **Adafruit MPU6050** and **Adafruit Unified Sensor** libraries if they are not already installed. The `Wire` and `BluetoothSerial` libraries are supplied with the relevant Arduino-ESP32 core.
4. Select the correct ESP32 board and port.
5. Wire the flex sensors, MPU6050, and relay inputs according to the pin table and your board's electrical requirements.
6. Upload the sketch and open Serial Monitor at **115200 baud**.
7. Pair a Bluetooth Classic-capable Android device with **SenseSpeak** and test the stream with a serial Bluetooth terminal or the companion app.

### Troubleshooting

- **MPU6050 initialization fails:** Check power, ground, I²C wiring, and the board's configured I²C pins.
- **Flex states never change:** Inspect the voltage-divider wiring and analog readings; recalibrate `FLEX_THRESHOLD`.
- **Relay behavior is reversed:** Confirm whether the relay module is active-low or active-high before changing the logic.
- **Bluetooth is not visible:** Confirm that the board supports Bluetooth Classic and that the correct ESP32 board/core is selected.

## Current Scope & Future Improvements

The checked-in sketch implements threshold-based gesture mapping, Bluetooth serial output, relay actions, and a simple acceleration threshold event. Potential next steps include:

- Calibrating flex-sensor thresholds for different users and glove fits.
- Improving motion-event logic to reduce false positives and validate it with collected test data.

## Safety & Limitations

Gesture recognition depends on sensor placement, calibration, and individual hand movement. The fall-detection logic is a basic prototype and must not be relied on for emergency or medical decisions. Test relay outputs with safe low-voltage loads and appropriate electrical isolation.
